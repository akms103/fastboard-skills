# Триггеры Fastboard: переменные → события → видимость → переходы

Механика одна на все случаи: **объект пишет булеву переменную страницы, другой объект
на неё подписан**. Связку «переменная = true → показать виджет» исполняет движок платформы
в рантайме — **в JSON её нет, искать бесполезно**. В файле лежат только писатель, приёмник
и стартовое `isVisible`.

Логика ниже проверена на живых импортах: страница с попапом и парными переключателями
собралась, залилась и отработала в UI.

## Шаг 0. Что выяснить из файлов, а не спрашивать

- **Переменные страницы** — `pagesSettings[0].page.variables`: `{id, name, type: "boolean",
  status: "true"|"false"}`. Статус — стартовое значение, не «сравнение».
- **Образцы событий** — возьмите боевую выгрузку страницы, где триггеры уже работают, и
  скопируйте оттуда полный объект `events` (и своих доноров по типу виджета).
- **Тип виджета-активатора** — обычно `text` (маленькая кнопка/стрелка), но писателем может
  быть любой виджет.
- **Затемнение** — цвет с `opacity < 100` из палитры проекта; если такого нет, его надо
  добавить в группу палитры (см. `fastboard-palettes`), а не подбирать hex в виджете.

## Шаг 1. Объявить переменные

```json
"variables": [
  { "id": "<uuid>", "name": "Попап детализации", "type": "boolean", "status": "false" },
  { "id": "<uuid>", "name": "Показывать поток", "type": "boolean", "status": "true" }
]
```

Одна переменная может управлять целой группой объектов. Стартовый `status` должен совпадать
со стартовым `isVisible` приёмников: скрытый попап → переменная `false`, его виджеты
`isVisible: false`.

## Шаг 2. События: писатель и приёмник

`events` есть у каждого виджета; для триггеров нужен блок `variablesSettings`:

```jsonc
"variablesSettings": {
  "mode": "common",
  "control": { "view": { "isActive": false, "variableId": "", "variableName": "" } },
  "matches": [],
  "isActive": false,          // true = виджет ПИШЕТ переменные по клику
  "variables": [],            // что именно писать
  "separatedModeVariables": []
}
```

**Писатель** (кнопка, стрелка, фон, крестик) — `isActive: true` + записи:

```jsonc
"isActive": true,
"variables": [
  { "id": "<uuid-записи>", "status": "true",   "variableId": "<id переменной>" },
  { "id": "<uuid-записи>", "status": "false",  "variableId": "<id другой переменной>" }
]
```

`status` — это **присваиваемое** значение: `"true"` включить, `"false"` выключить,
`"invert"` инвертировать текущее. Одна кнопка может писать сразу несколько переменных.

**Приёмник** (то, что появляется/исчезает) — подписка через `control.view`:

```jsonc
"control": { "view": { "isActive": true, "variableId": "<id переменной>", "variableName": "Попап детализации" } }
```

Виджет может быть **одновременно приёмником и писателем** — это и есть штатный способ
сделать «фон закрывает попап» и «крестик закрывает попап»: у обоих заполнены и
`control.view`, и `variables[]` со `status:"false"`.

`isVisible` — только стартовое состояние, оно не связано с переменной в файле.

## Шаг 3. Паттерн «попап» (основной)

Пять объектов, одна переменная:

| Объект | Видимость | Роль | Что настроить |
|---|---|---|---|
| Карточка/виджет-источник | всегда | — | ничего |
| Стрелка «⤢», 36–40 × 36–40 px, поверх источника в правом верхнем углу | всегда | писатель | `isActive:true`, `status:"true"` |
| Подложка на всю доску | скрыта | приёмник + писатель | `control.view` + `status:"false"`, фон — полупрозрачный цвет палитры |
| Панель детализации (по центру) | скрыта | приёмник | `control.view`, фон карточки, рамка |
| Крестик «✖» в углу панели | скрыт | приёмник + писатель | `control.view` + `status:"false"` |

Так «один триггер управляется из разных объектов»: стрелка открывает, фон и крестик закрывают.
Стрелка должна лежать **выше** источника по слоям, панель и подложка — **выше** всего контента.

Подложка на всю доску обязана быть полупрозрачной: фон `styleContainerSettings.…background.color`
= ссылка на цвет палитры с `opacity < 100`. Иначе получится белая заглушка, а не затемнение.

## Шаг 4. Паттерн «парные переключатели»

Взаимоисключающие режимы: кнопка ставит **себя в true, соседей в false** одним кликом.

| Пара/тройка | Кнопка пишет |
|---|---|
| `Руб.` ⇄ `%` | `Руб.=true, %=false` / `%=true, Руб.=false` |
| `Приоритет` ⇄ `Текущие` | `Приоритет=true, Текущие=false` / наоборот |
| `Детализация` / `Отклонение` / `Движение` | каждая: себя `true`, двух других `false` |
| `Итоги` ⇄ `Динамика` (Σ/Δ) | `Итоги=true, Динамика=false` / наоборот |
| `Группа 1` ⇄ `Группа 2` | себя `true`, соседа `false` |

Тумблер «включить/выключить» на одной переменной — `status: "invert"`.

## Шаг 5. Переходы

```jsonc
// на страницу дашборда
"goTo": { "to": { "id": "<pageId>", "type": "page" }, "isActive": true }

// внешняя ссылка
"goToHref": { "to": "https://…", "isActive": true, "openWindowType": "self" }  // или "blank"

// расширенная форма (обычно не нужна, но живёт рядом)
"transitionSettings": {
  "isActive": true, "typeTransition": "object", "openWindowType": "self",
  "settings": { "object": { "common": { "pageTo": "<pageId>" }, "separated": { "links": [] } },
                "hyperlink": { "common": { "link": "" }, "database": { "fieldName": null },
                               "separated": { "links": [] } } }
}
```

`to: null` при `isActive: true` — «полунастроенный» переход-артефакт; трактуйте как выключенный.

## КРИТИЧЕСКИЕ ГРАБЛИ

1. **`isGrouped: true` при пустом `groupId` — виджет не отрисовывается вообще.** Самая
   дорогая ошибка. Текст-виджеты в донорах лежат внутри групп; при клонировании `groupId`
   обнуляется как чужой, а `isGrouped` остаётся `true`. Итог: **все text-виджеты (KPI-карточки,
   шапки, плашки, активаторы, подложка) невидимы, а таблицы и графики видны**. Лечение —
   явно ставить `viewSettings.group.isGrouped = false` **всем** виджетам после клонирования.
   Проверка: `scripts/check_triggers.py` падает на этой комбинации.
2. **Связки «переменная → видимость» в JSON нет.** Не ищите `visibleBy`/`showBy`/`conditionVisibility`
   — их не существует. Работает только пара «писатель + `control.view`», остальное делает движок.
3. **Не переводите цвета текста на «уровни темы» ради видимости.** Палитра в текстах работает
   (так красят боевые страницы и доноры). Если текст не виден — ищите причину в `isGrouped`,
   геометрии и слоях, а не в цвете. Это проверенная ложная тропа.
4. **Слои (`indeces.layers`) — порядок отрисовки снизу вверх.** Попап-объекты (стрелка,
   подложка, панель, крестик) обязаны быть в конце списка, иначе их перекроют карточки.
5. **Импорт с `newPages: "true"` создаёт новую страницу с новым серверным id** — id из файла
   не сохраняется. Каждая итерация = новый лист; старые дубли удаляйте вручную.
6. **«Мёртвые» привязки.** У многих донорских виджетов `control.view.isActive: true`, но
   `variableId: ""` и `variableName: "Выручка"`. Это остаток конфигурации, а не привязка:
   чистите до `{isActive:false, variableId:"", variableName:""}`.
7. **Переменная обязана существовать в `page.variables`** — иначе событие молча не сработает.
   `invert` допустим только для `boolean`.

## Порядок сборки

1. объявить переменные в `page.variables`;
2. клонировать виджеты-доноры по типу;
3. сантайз чужого (SQL, чужие `colorId`/`groupId`, ссылки на чужие страницы/переменные);
4. нормализация — в том числе **`isGrouped=false` всем**;
5. проставить триггеры: писателям `variablesSettings`, приёмникам `control.view`;
6. собрать `indeces.layers` снизу вверх: тексты → графики/таблицы → попап → фильтры;
7. прогнать `scripts/check_triggers.py`;
8. залить страницу через MCP (`fastboard-mcp-master`, конверт `file:{contentType, encoding, data}`).

## Проверка

```bash
python scripts/check_triggers.py page.json
```

Скрипт читает **готовый** файл (не сборщик) и падает с кодом 1, если:

- у виджета `isGrouped: true` без `groupId` (виджет не отрисуется);
- писатель или приёмник ссылается на переменную, которой нет в `page.variables`;
- `status` записи не из `true`/`false`/`invert`, либо `invert` у не-булевой переменной;
- `isActive: true` при пустом `variables[]`;
- `indeces.layers` содержит дубли;
- id виджетов дублируются.

Предупреждения (не ошибки, код возврата 0): «мёртвые» `control.view` (активен при пустом
`variableId`, выводится одной сводной строкой), нет объекта в `layers` или там лишние id —
платформа подставит порядок из массива виджетов, это риск перекрытия, а не поломка триггера.
`--strict` превращает предупреждения в ошибки, если нужен чистый прогон.

## Что подтверждено, а что нет

| Проверено на импорте | Требует проверки глазами |
|---|---|
| писатель `isActive + variables[]`; приёмник `control.view`; объект одновременно и то и другое; `status` `true`/`false`/`invert`; стартовое `isVisible`; попап со стрелкой, подложкой и крестиком; `isGrouped=false` как лечение невидимых текстов | поведение `invert` на не-boolean; приоритет `transitionSettings` над `goTo` при обоих активных; как платформа ведёт себя при двух приёмниках одного объекта в разных группах |

## Ловушки (чек-лист)

- [ ] `isGrouped=false` у всех виджетов; `groupId=null`.
- [ ] Каждая переменная из событий есть в `page.variables` с тем же `id`.
- [ ] Писатель: `isActive:true` и непустой `variables[]`; `status` из `true/false/invert`.
- [ ] Приёмник: `control.view.isActive:true` и заполненный `variableId`.
- [ ] Фон-подложка и крестик — и приёмники, и писатели `false`.
- [ ] Подложка полупрозрачная (цвет палитры с `opacity<100`), а не белая.
- [ ] Попап-объекты выше контента в `indeces.layers`.
- [ ] Стрелка-активатор в правом верхнем углу источника, 36–40 px, не перекрыта.
- [ ] Мёртвые `control.view` («Выручка», пустой id) вычищены.
- [ ] `scripts/check_triggers.py` вернул 0.
