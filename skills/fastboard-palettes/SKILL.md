# Палитры Fastboard: создать → описать ролями → применить → проверить

Работа идёт по четырём артефактам, и все четыре остаются в проекте:

1. **`colors.json`** — реестр групп цветов (`{id, name, colors[{h,l,s,id,hex,name,opacity}]}`);
2. **файл ролей** — что куда ставится: фон страницы, фон виджета, серии, разрез, тексты
   (`templates/palette-roles.json` + `scripts/palette.py`);
3. **собранная страница** — в ней нет hex: только ссылки на группу и цвет;
4. **отчёт проверки** — `scripts/check_colors.py` (код возврата 1, если ссылки мертвы).

Логика ниже проверена на живом импорте: группа, созданная локально (`uuid4`), и страница
со ссылками на неё загрузились и отрисовались в заданных цветах.

## Шаг 0. Что выяснить из файлов, а не спрашивать

- **`paletteId`** — id палитры проекта. Он лежит **ключом** любой цветовой ссылки в боевой
  выгрузке страницы и берётся оттуда:
  `"elementColor": {"55f43476-…": {"type": "color", "groupId": …, "colorId": …}}` → `paletteId`
  = `55f43476-…`. Другие источники: API палитр (`ExportPaletteInterface {projectId, paletteGroups}`),
  выгрузка настроек темы.
- **группы и цвета** — из `colors.json` проекта (или из выгрузки страницы, где они уже стоят).
- **какие виджеты уже раскрашены** — по путям из таблицы шага 3: если `colorId` там `null`,
  виджет цвета не имеет и наследует палитру темы.

Не спрашивайте то, что видно в файлах: какой `paletteId`, какие группы есть, какие роли заняты.

## Шаг 1. Создать или взять группу цветов

```
python scripts/add_palette.py colors.json "Газпром" \
    "#0079c2:Газпром синий:100" "#4fa3db:светлый" "#00395c:тёмно-синий" "#ffffff:белый"
```

Две формы записи цвета (можно смешивать в одной команде):

| форма | как пишется | когда |
|---|---|---|
| hex-first | `"#0079c2:имя:opacity"` | обычный случай: HSL считается из hex |
| позиционная | `H L S "#hex" "имя"` | когда h/l/s заданы вручную (например, из HSL-пикера) |

`opacity` опускается — будет 100. Если заданы и h/l/s, и hex, скрипт сверит их между собой
и предупредит о расхождении больше 2°.

Группа получает новый `uuid4` — id можно создавать самим: проверено, что проект принимает
группу, созданную вне UI.

## Шаг 2. Описать роли

Скопируйте `templates/palette-roles.json` и заполните: `paletteId`, `groupsFile` (или группы
inline), затем роли. Ролей две разновидности, и это не придирка, а разные механизмы платформы:

| разновидность | роли | что нужно в файле | что уезжает на страницу |
|---|---|---|---|
| палитровые | `page_background`, `widget_background`, `incision_palette`, `series_1…4` | `groupId` (+ `colorId`, кроме разреза), `hex` | ссылка на цвет или на группу |
| текстовые | `header_text`, `caption_text`, `value_text`, `unit_text` | `level` 1–5, `hex` | уровень темы, **не** палитра |

`hex` нужен у **всех** ролей, а не только у текстов: по нему собирается HTML-предпросмотр, и он же
требуется проверкой `palette.py` — без оттенка она останавливает сборку («макету нечего красить»).

`level` обязан быть целым 1–5: `palette.py` проверяет и диапазон, а не только «это число».

```
python scripts/palette.py my-palette.json      # покажет, что заполнено, а что ждёт id
python -c "import sys; sys.path.insert(0,'scripts'); from palette import Palette, ROLE_SERIES;\
p=Palette.load('my-palette.json'); print(p.color_ref(ROLE_SERIES[0]))"
```

Проверка обязана провалиться, если хоть один `colorId`/`groupId` оставлен плейсхолдером:
пустая ссылка хуже отсутствия ссылки.

## Шаг 3. Применить к странице

Две формы ссылок — **ключ словаря всегда id палитры**, не id страницы:

```json
// цвет из группы — серии, фоны, конкретные элементы
"elementColor": {"<paletteId>": {"type": "color", "groupId": "<группа>", "colorId": "<цвет>"}}

// группа целиком — категории разреза берут цвета по порядку
"elementColor": {"<paletteId>": {"type": "palette", "groupId": "<группа>"}}
```

| Что | Путь в JSON страницы | Форма |
|---|---|---|
| Фон страницы | `pagesSettings[].page.color.color` | ссылка на цвет |
| Фон виджета | `viewSettings.styleContainerSettings.backgroundSettings.colorSettings.background.color` | ссылка на цвет |
| Серия показателя | `dataSettings.indicators[].settings.elementSettings.colorBySettings.elementColor` | ссылка на цвет |
| Подписи значений серии | `dataSettings.indicators[].settings.showValue.colorBySettings.elementColor` | ссылка на цвет |
| Разрез: категории из группы | `dataSettings.incisions[].colorBySettingsValueAndElement.colorBySettingsElement.elementColor` | ссылка на группу (`type:"palette"`) |
| Разрез: по значениям | `dataSettings.incisions[].colors` | массив `[{value, colorId, groupId}]` |
| Тексты: заголовок, легенда, оси, единицы, итог стопки | `…fontColor` в `header`, `legendSettings.properties`, `axisIncisionSettings`/`axisIndicatorSettings`/`axisAdditionalIndicatorSettings.label.properties`, `indicators[].settings.showValue.properties`, `secondaryProperties`, `indicatorsStackSum[].settings.showValue.properties` | уровень темы `{<pageId>: {type:"color", level:1…5}}` |
| Панель инструментов, тени, рамка | `viewSettings.toolboxSettings`, `styleContainerSettings` | не палитра: выключать, а не красить |

Серии в одной стопке обязаны иметь **разные** `colorId` — иначе стопка читается как одна серия.

## Шаг 4. Порядок обработки: sanitize → нормализация → палитра

Палитра ставится **последней**. Иначе её снесёт собственная чистка:

1. клон донора и сантайз чужих ссылок (SQL, чужие `colorId`/`groupId`, алиасы, uuid-ключи);
2. нормализация настроек (шрифты, оси, отступы, контуры контейнера);
3. **раскраска по ролям** — здесь и только здесь появляются id своей палитры.

Три ловушки, каждая из которых молча оставит страницу бесцветной:

- **`colorId`, `groupId`, `elementColor`, `colors` не входят в список обнуляемых ключей.**
  Если сантайз чистит `colorId` «как чужой», палитра не доедет.
- **uuid-ключ палитры нельзя переписывать.** Обычная нормализация «любой чужой uuid-ключ →
  id страницы» уничтожает ключ ссылки: `{paletteId: {…}}` → `{pageId: {…}}`, и цвет теряется.
  Держите исключение для ключа, равного `paletteId`.
- **Уровни темы для текстов ключуются id страницы** (это отдельный механизм, не палитра).
  Если положить в `fontColor` ссылку на палитру, платформа может проигнорировать цвет;
  в боевых выгрузках встречается и вариант с ключом-`paletteId` — проверяйте на импорте.

## Шаг 5. Проверить, что применилось

```
python scripts/check_colors.py page.json --palette my-palette.json --palette-id 55f43476-…
```

Скрипт — **отдельный модуль от сборщика** (сборщик видит только то, что сам проставил):
читает готовый файл, показывает, что стоит в четырёх местах задания (фон страницы, фоны
виджетов, тексты, разрезы и серии), сверяет каждый `colorId` с группами палитры и падает
с кодом 1, если ссылка пустая, ведёт на несуществующий цвет, ключ ссылки не равен `paletteId`
или в обязательном месте стоит «цвет по умолчанию темы» (`{type:"color", colorId:null,
groupId:null}` — ссылка законная, но палитра там не применена).

Дальше — приёмка стиля: `skills/bi-dashboard-styleguide/scripts/check_style.py` (соседний скилл
репозитория). Раскраска палитрой
и нейтральный стайлгайд расходятся по определению (заливка карточек, свои серии), поэтому
отклонения фиксируются решением заказчика, а не «исправляются» молча.

## Что подтверждено, а что нет

| Проверено на импорте | Требует образца |
|---|---|
| группа с локальными `uuid4`; ссылки на цвет для фона страницы, фона виджета, серий и подписей значений; ссылка на группу для разреза; уровни темы для текстов | ссылки на палитру **в текстах** (`fontColor` с `colorId`) |
| `paletteId` как ключ ссылки | форма `incisions[].colors` массивом значений — для сегментов круговой; для столбцов по времени обычно нужна ссылка на группу |
| — | читает ли платформа `colors.json` сама или это локальный реестр, из которого id попадают в проект |

## Ловушки (сокращённый чек-лист)

- [ ] `paletteId` известен и стоит ключом у каждой ссылки — не id страницы.
- [ ] Ни одна роль не оставлена с плейсхолдером; `scripts/palette.py` проходит без ошибок.
- [ ] `colorId`/`groupId`/`elementColor`/`colors` не в списке обнуляемых ключей сантайза.
- [ ] Исключение для uuid-ключа, равного `paletteId`, есть в нормализации.
- [ ] Палитра применяется последней; тексты получили уровни темы, а не палитру.
- [ ] В одной стопке у серий разные `colorId`.
- [ ] `scripts/check_colors.py` вернул 0; расхождения со стайлгайдом перечислены в отчёте.
- [ ] Чекер прогнан и по «тощей» странице (текстовый виджет без `header`, легенды и осей, страница
      без разрезов): он обязан выдать строки отчёта, а не упасть с `KeyError` — падение
      на живом экспорте выглядит как «проверку не делали».
- [ ] Файл палитры и `colors.json` лежат рядом с проектом: следующая правка идёт через них,
      а не «по месту» в странице.
