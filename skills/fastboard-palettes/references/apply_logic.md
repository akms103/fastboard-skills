# Логика применения палитры: роли → пути → порядок → проверка

Это описание конвейера, которым палитра попадает на страницу. Он проверен на живом импорте:
группа и страница со ссылками загрузились и отрисовались.

## 1. Решение принимается по ролям, а не по hex

Палитра проекта — это реестр цветов. Чтобы раскрасить страницу, нужно ответить не «какие это
оттенки», а **какая роль у каждого места**:

| роль | что это | разновидность |
|---|---|---|
| `page_background` | фон страницы | палитра (цвет) |
| `widget_background` | фон виджета | палитра (цвет) |
| `header_text` | заголовок виджета | уровень темы |
| `caption_text` | подписи осей, легенда, примечания | уровень темы |
| `value_text` | значения и подписи значений | уровень темы |
| `unit_text` | числа оси значений, акцент | уровень темы |
| `incision_palette` | цвета категорий разреза | палитра (группа) |
| `series_1…series_4` | серии показателей | палитра (цвет) |

Файл ролей (`templates/palette-roles.json`) держит для каждой роли `hex` (для макета), `level`
(для текстов) и `groupId`/`colorId` (для палитровых мест). Один файл на проект: правка цвета —
это правка роли, а не поиск hex по странице.

`scripts/palette.py` загружает такой файл, проверяет заполненность и собирает ровно те ссылки,
которые понимает платформа. Сборщик страницы только вставляет их по путям.

## 2. Порядок обработки: сантайз → нормализация → палитра

```
клон донора
  → сантайз чужих ссылок (SQL, чужие colorId/groupId, алиасы, uuid-ключи, палитры чужого проекта)
  → нормализация настроек (шрифты, оси, сетки, отступы, контуры контейнера, обвязка)
  → раскраска по ролям                 ← единственное место, где появляются id своей палитры
  → самопроверки сборщика
  → независимые чекеры (check_colors.py, check_style.py)
```

Па­литра обязана идти **последней**: любой шаг чистки после неё воспринимает её id как чужие.

## 3. Ловушки, из-за которых цвета не доезжают

1. **`colorId`, `groupId`, `elementColor`, `colors` в списке обнуляемых ключей.** Классический
   сантайз «обнулить всё, что похоже на чужой проект» сносит и палитру.
2. **Переписывание uuid-ключей.** Шаг «любой чужой uuid-ключ → id страницы» превращает
   `{paletteId: {...}}` в `{pageId: {...}}` — ключ ссылки перестаёт существовать, цвет теряется.
   Исключение для ключа, равного `paletteId`, обязательно.
3. **Палитра, поставленная раньше нормализации.** Нормализация тонов перезапишет `fontColor`
   и частично контейнеры.
4. **Серии одного цвета.** Если всем сериям стопки отдан один `colorId`, стопка читается как
   одна серия; цвета раздаются по кругу группы.
5. **Плейсхолдер вместо id.** Ссылка на несуществующий цвет — не «пусто», а битая ссылка:
   сборку лучше остановить, чем выпустить страницу с мёртвыми id.
6. **Роль текста, покрашенная палитрой.** Тексты живут на уровнях темы; палитровая ссылка в
   `fontColor` — эксперимент, а не рабочий приём (проверять на импорте).

## 4. Проверка применения

`scripts/check_colors.py` — отдельный модуль от сборщика: читает готовую страницу, показывает,
что стоит в четырёх местах задания, и падает с кодом 1, если:

- ссылка пустая там, где по ролям обязана быть (фон страницы, фоны виджетов, серии);
- в обязательном для палитры месте стоит «цвет по умолчанию темы» — `{type:"color", colorId:null,
  groupId:null}`: ссылка законная (так залиты белые карточки), но палитра там не применена;
- `colorId` не найден ни в одной группе поданного файла палитры;
- ключ ссылки не равен ожидаемому `paletteId` (значит ссылку поставили не туда);
- встретилась ссылка неизвестной формы (ни `color`, ни `palette`, ни `level`).

Отдельно от него — стилевая приёмка (`bi-dashboard-styleguide/scripts/check_style.py`):
раскраска палитрой и нейтральный стайлгайд расходятся (заливки карточек, цветные серии,
корпоративные оттенки). Расхождения фиксируются решением заказчика в отчёте, а не правятся молча.

## 5. Что смотреть глазами после импорта

- применился ли фон страницы и фоны виджетов (это видно сразу);
- читается ли текст на новых фонах (палитра может дать тёмный фон);
- не перекрыла ли группа разреза цвета серий — если да, отдать разрезу один цвет или убрать
  ссылку на группу;
- совпали ли подписи осей и легенда с ожидаемым тоном: если текст уехал в «системный» цвет,
  значит ключ уровня темы в вашей версии платформы другой (страница/палитра).
